# Форма — цифровой дизайнер презентаций

Локальный сервис: PPTX-шаблон + содержание → три редактируемые презентации,
PDF, HTML и отчёт проверок. Python/FastAPI, React, OOXML, LibreOffice/Poppler.
Исходные материалы сохраняются; результаты и исправления имеют отдельные версии.

**Статус:** работающий прототип. Диагностический режим и реальные шаблоны проверены.
Живой LLM/VLM не проверен без реквизитов разрешённой модели. Поддержка SmartArt
ограничена двумя описанными топологиями. Точная сохранность фирменного стиля на
любом файле не гарантируется: для этого есть профиль, рендер, аудит и ограничения.
Фактические результаты — в [docs/verification.md](docs/verification.md).

## Запуск в Docker

```sh
docker compose up --build
```

Открыть http://localhost:8000. Данные хранятся в томе `lct-data`.
Сервис привязан к localhost. Публичное размещение, авторизация и многопользовательская
изоляция не реализованы. Модели по умолчанию не вызываются и расходы на API отсутствуют.

## Разработка / CLI

Python 3.12+, Node.js 22+, Docker Desktop. Из корня репозитория:

```sh
python -m venv .venv
# Windows: .venv/Scripts/python.exe; Unix: .venv/bin/python
.venv/Scripts/python.exe -m pip install -r requirements.lock
.venv/Scripts/python.exe -m pip install --no-deps -e .
npm ci --prefix frontend
npm run build --prefix frontend
docker build -f docker/Renderer.Dockerfile -t lct-design-renderer:local .
.venv/Scripts/lct-design.exe serve
```

```sh
lct-design analyze template.pptx --output output/profile.json
lct-design generate --template template.pptx --content examples/content.json --output output/demo --variants sequential comparison focus
python scripts/demo.py --dataset path/to/dataset --output output/matrix
python -m pytest -q
```

В разработке API работает на 8000; `npm run dev --prefix frontend` — интерфейс на 5173.
Для браузерных тестов запустить отдельный сервер на 8012; задать `LCT_TEST_TEMPLATE`
путём к своему PPTX и выполнить `npx playwright test` из frontend.
Версия браузера берётся из Playwright; при отсутствии: `npx playwright install chromium`.

## Содержание и режимы

В интерфейсе доступны бриф, JSON/Markdown/TXT и демонстрационный пакет.
`examples/content.json` содержит 12 разделов и **синтетические** числа.
Официальный контент организатора в предоставленных файлах не найден.

JSON: `title`, `sections`, `synthetic`; каждый раздел имеет уникальный `id`, `title`,
`bullets` и не более одной визуализации:

- `table`: прямоугольный массив строк, максимум 40 × 12;
- `chart`: `categories`, `series` (1–5 числовых рядов), `title`, `unit`;
- `image`: PNG/JPEG data URI ≤8 МБ / 25 млн пикселей. Пути и URL не загружаются;
- `diagram`: подписи узлов; `diagram_kind`: process/hierarchy.

Для hierarchy `diagram_parents` задаёт индекс родителя каждого узла, первый — null,
остальные ссылаются на предшествующий узел; по умолчанию корень → остальные узлы.
Native SmartArt: процесс ровно из 4 шагов; организация из 6 узлов с
`diagram_parents: [null,0,0,0,0,2]`, `diagram_assistant: 1` (корень, помощник,
три подразделения, сотрудник первого подразделения). Другие структуры представлены
редактируемыми фигурами со связями и явным предупреждением, а не названы SmartArt.

В режиме без модели исходные разделы сохраняются без выдуманных фактов. Запрошенное
число слайдов может отличаться от фактического — причина указывается в результате.
Для AI-режима см. [MODELS.md](MODELS.md). Адрес совместимого API, ключ и модели
задаются на странице «Настройки AI» либо через окружение. Сохранённый ключ остаётся
на сервере и не возвращается браузеру. `.env` используется Compose; для CLI переменные
должны быть установлены в окружении процесса. Запуск со своими данными и на своём
домене, CI/CD для `forma.inflake.fun`: [QUICKSTART.md](QUICKSTART.md).

## Что сохраняется

`data/templates/<id>/`: оригинал, извлечённый профиль и анализ.
`data/jobs/<id>/`: план, профиль, отчёт запуска, каталоги вариантов.
Вариант: `presentation.pptx`, `presentation.html`, `source.pdf`, `slide-*.png`,
`speech.md`, `manifest.json`, `audit.json`, `render.json`. Текст выступления также
встроен в заметки каждого слайда PPTX и доступен в интерфейсе. Он составлен из
исходных фактов, включая таблицы и числа графиков; длительность дана как оценка
при 130 словах/мин, без обещания уложить произвольный объём в семь минут.
PDF отсутствует при неудаче renderer;
интерфейс показывает частичный результат. HTML включает реальные превью, PPTX — native объекты.

Архитектура: [ARCHITECTURE.md](ARCHITECTURE.md). Проверки: [AUDIT.md](AUDIT.md).
Питч: `python scripts/pitch.py --template path/to/ЛЦТ2026.pptx --output output/pitch`.
Обязательные исходные слайды 7–11 сохраняют дизайн/структуру и составляют начало питча.
Без фактов о команде результат остаётся черновиком, не готовой заявкой.

`run.json → timing` разделяет подготовку шаблона и генерацию **всех трёх вариантов
с текстом выступления**. Бюджет — 300 секунд после подготовки. `met` означает
только соблюдение времени; ошибки качества перечислены в аудите отдельно.
Офлайн-замер не доказывает скорость внешней модели. Подготовленный профиль
повторно используется при выборе уже загруженного шаблона.

Материалы и правила фиксации версии: [docs/submission.md](docs/submission.md).

## Лицензия и источники

Новый код — MIT. SmartArt fixture — MIT, [атрибуция](third_party/ts-pptx/README.md).
Шаблоны и материалы организатора не включены в Git. LibreOffice/Poppler устанавливаются
как отдельные системные программы с собственными лицензиями.
В live-пайплайне действуют правила визуальной иерархии, читаемости и сохранения
бренда: при выборе композиций, пакетной визуальной проверке и одном проходе
исправлений. Исходное оформление шаблона имеет приоритет.

В репозитории публикуются код, тесты и инструкции. Входные материалы, результаты,
локальные настройки, ключи, временные файлы и история инструментов разработки
исключены через `.gitignore`; уже созданные локальные файлы при этом сохраняются.

## Сохранение оформления

Генератор сохраняет фон выбранного исходного слайда, мастер/макет, изображения,
логотипы и визуальное оформление фигур (заливку, границу, эффекты, положение).
При замене текста очищается текстовое содержимое, а не вся фигура. Колонтитулы
сохраняются. Размер или редкость изображения не служат причиной его удаления.
Неоднозначные фотографии шаблона также сохраняются: автоматическое различение
фотопримера и фирменного изображения пока не гарантируется. Исходные таблицы и
диаграммы считаются содержимым и заменяются новыми объектами.
При выборе композиции учитываются пересечения с картинками; значимые исходные
текстовые области не расширяются через соседние карточки. Это эвристика, которая
не гарантирует распознавание иллюстраций внутри единого фонового изображения.
