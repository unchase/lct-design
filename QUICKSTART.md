# Форма: локальный запуск и свой домен

Рекомендуемый первый запуск — Docker на своём компьютере: данные остаются в
локальном томе, внешний AI включается отдельно. Для `forma.inflake.fun`
подготовлена схема: registry → Docker Compose → существующий
Traefik в сети `intranet`. Новые облачные сервисы и отдельный runner не нужны.

Это инструкция и конфигурация, а не подтверждение публикации: DNS, registry,
сервер и сертификат проверяются при фактическом развёртывании.

## 1. Запустить на своём компьютере

Нужны Git и Docker с Linux containers, Compose 2.24+; образ содержит Python,
Node-сборку интерфейса, LibreOffice и Poppler. Контейнер ограничен 2 CPU и 3 ГБ
RAM; на машине нужен запас для Docker, сборки и хранения результатов.

На своём компьютере, в терминале:

```sh
git clone https://github.com/unchase/lct-design.git
```

Перейти в скачанную папку:

```sh
cd lct-design
```

Создать свой файл настроек. PowerShell:

```powershell
Copy-Item .env.example .env
```

Для Linux/macOS та же операция:

```sh
cp .env.example .env
```

Запустить локальное приложение из корня проекта:

```sh
docker compose up -d --build
```

Открыть [http://localhost:8000](http://localhost:8000). Проверка запуска:
[http://localhost:8000/api/health](http://localhost:8000/api/health) возвращает
`"status":"ok"`. `live_configured:false` допустимо до настройки AI.
Локальный порт доступен только с этого компьютера. Если `LCT_ACCESS_TOKEN`
заполнен, браузер спросит логин `forma` и пароль из этой переменной.

Остановить приложение без удаления данных:

```sh
docker compose stop
```

## 2. Подключить свой API

В интерфейсе открыть настройки AI. Выбрать OpenRouter либо совместимый
провайдер, ввести адрес API, свой ключ и точный ID модели, затем сохранить и
проверить соединение. Для OpenRouter адрес API —
`https://openrouter.ai/api/v1`; приложение добавляет `/chat/completions` само.
Для другого провайдера нужен его совместимый базовый адрес, обычно с `/v1`.

Ключ хранится на сервере в каталоге данных; интерфейс не получает сохранённый
ключ обратно. Не вставлять его в содержание слайдов, Git, чат или скриншоты.
Сохранённые настройки интерфейса имеют приоритет над переменными `.env`.

Если настройки передаются через окружение, заполнить свой `.env`. В `.env.example`
уже указаны OpenRouter и модель из условий задачи — `qwen/qwen3.8-27b`
(Qwen3.8-27B: открытые веса, Apache-2.0, 27,8B параметров, принимает изображения,
поэтому она же выполняет визуальную проверку). Достаточно вписать свой
`LCT_API_KEY`; без ключа AI для OpenRouter остаётся выключенным. Для другого
провайдера заменить адрес и ID моделей:

| Переменная | Значение |
|---|---|
| `LCT_API_BASE` | Базовый URL OpenAI-compatible API |
| `LCT_API_KEY` | Секретный ключ провайдера |
| `LCT_MODEL` | Точный ID модели из каталога своего провайдера |
| `LCT_COMPETITION_MODE` | `true` для ограничений конкурса; `false` для личного использования других моделей |
| `LCT_MODEL_LICENSE` | Проверенная лицензия модели, для конкурса Apache-2.0 или MIT |
| `LCT_MODEL_PARAMETERS_B` | Полное число параметров в миллиардах; в конкурсном режиме не более 35 |
| `LCT_MODEL_CARD` | Ссылка на карточку модели, подтверждающую сведения |
| `LCT_VISION_ENABLED` | `true` только для провайдера/модели с поддержкой изображений |
| `LCT_VISION_MODEL` | ID модели для визуальной проверки |
| `LCT_VISION_LICENSE`, `LCT_VISION_PARAMETERS_B`, `LCT_VISION_CARD` | Подтверждённые сведения о визуальной модели |

После изменения `.env` применить настройки локального контейнера:

```sh
docker compose up -d --force-recreate
```

Это не перезаписывает уже сохранённые настройки AI: их меняют в интерфейсе.
Точные требования и ограничения — в [MODELS.md](MODELS.md).

Без AI внешние запросы не выполняются. Проверка соединения и живой режим могут
расходовать лимит провайдера; исходный текст, а при визуальной проверке и
изображения слайдов, уходят на выбранный сервер. Рекомендуется отдельный ключ
с ограниченным бюджетом. Конкретная стоимость зависит от модели и тарифа.

## 3. Использовать свои материалы

Загрузить свой PPTX-шаблон через интерфейс. Затем добавить содержание: бриф,
JSON, Markdown или TXT. Структура JSON показана в `examples/content.json`;
демонстрационный пример содержит синтетические числа.

Сначала выполнить пробную генерацию без AI и проверить PPTX/PDF. Для своих
данных заменить демонстрационные факты. Внешний AI включать после настройки
провайдера. Проверять отчёт, предпросмотр и редактируемость итогового PPTX.

Локально шаблоны, задания, результаты и настройки провайдера находятся в томе
Compose `lct-data` (имя Docker обычно содержит префикс проекта). В публичной
конфигурации используется отдельный том **`forma-data`**. Данные между ними
автоматически не переносятся. Не выполнять `docker compose down -v`, если
данные нужны: этот флаг удаляет тома проекта.

## 4. Публикация `forma.inflake.fun`

### Что уже подготовлено в репозитории

- `.github/workflows/ci.yml`: Python-тесты, сборка интерфейса, Docker-сборка,
  запуск контейнера и браузерные проверки на GitHub-hosted runner.
- После успешных проверок публикация образа в
  `${REGISTRY_HOST}/inflake/forma:<полный SHA>` и `:main` на существующем
  Windows runner с метками `self-hosted, forma-builder`.
- `compose.production.yaml`: HTTPS через Traefik, обязательный пароль,
  постоянный том, ограничения ресурсов, проверка работоспособности.
- GitHub публикует **только образ**. Фактическое обновление приложения выполняет
  существующий Watchtower после явного включения либо команда Compose на сервере.

Браузерный сценарий полной генерации требует своего PPTX через
`LCT_TEST_TEMPLATE` и без него пропускается; CI не загружает частные шаблоны.
Успешная сборка не доказывает качество живой модели или доступность домена.

### Однократная настройка GitHub

В репозитории создать окружение **production**, ограничить его основной веткой
(`master` в текущем репозитории; workflow поддерживает также `main`)
и включить обязательное подтверждение выпуска доступными средствами GitHub.
Защиту окружения нужно настроить вручную: файл workflow её не создаёт.

В этом окружении добавить секреты, вводя значения непосредственно в GitHub:

| Secret | Назначение |
|---|---|
| `REGISTRY_HOST` | Имя registry без `https://`, обычно `registry.inflake.fun` |
| `REGISTRY_USER` | Пользователь с правом публикации `inflake/forma` |
| `REGISTRY_PASS` | Пароль/токен registry |

Runner с меткой `forma-builder` должен быть разрешён этому репозиторию, иметь PowerShell
и Docker с Linux containers и доступ к registry. Ни один job pull request
не попадает на этот runner и не получает эти секреты.
Метка задаётся через repository variable `FORMA_RUNNER_LABEL`; по умолчанию
`forma-builder`. Можно добавить эту метку существующему Windows runner, сохранив
его прежние метки и доступ других проектов. Новый сервер сборки для этого не нужен.

Первый выпуск: **Actions → CI and Docker image → Run workflow → основная ветка →
publish = true**. Проверки проходят до публикации; затем применяется защита
окружения `production`. Workflow должен сначала попасть в основную ветку.

По умолчанию push в `master`/`main` запускает проверки без публикации. Для дальнейших
автоматических выпусков администратор может задать repository variable
`LCT_AUTO_PUBLISH=true`; защита `production` продолжит применяться. Это
осознанно включает замену образа после изменений в основной ветке. Публикация
разрешена только из текущей default branch репозитория; тег образа остаётся `main`.

### Однократная настройка сервера Inflake

На сервере нужны существующий Traefik с resolver `leresolver`, его Docker-сеть
`intranet`, доступ к registry и право получить сертификат на домен. DNS:
запись **A** для `forma.inflake.fun` указывает на публичный IPv4 именно этого
сервера. **AAAA** добавляется только при рабочем IPv6 на том же сервере.
Адрес сервера не выводится из имени registry и здесь не предполагается.
Порты 80/443 должны доходить до Traefik.

Скопировать на сервер репозиторий или как минимум `compose.production.yaml`
и `.env.example` в отдельный каталог Forma. Создать `.env` из примера и
заполнить **`LCT_ACCESS_TOKEN`** длинным случайным паролем, хранить файл только
у администратора. Публичный Compose откажется запускаться с пустым паролем.
`LCT_DOMAIN=forma.inflake.fun`; для своего домена изменить эту переменную.
Compose автоматически задаёт `LCT_PUBLIC_URL=https://` с этим доменом для
проверки источника браузерных запросов за HTTPS-прокси. Домен должен совпадать
с адресом, который открывают пользователи; в локальном `.env` URL оставляют пустым.
Пароль доступа к приложению отличается от ключа провайдера AI.

На сервере, из каталога Forma, войти в registry (пароль вводится в приглашении):

```sh
docker login registry.inflake.fun
```

На сервере скачать уже опубликованный образ:

```sh
docker compose -f compose.production.yaml pull
```

На сервере запустить приложение:

```sh
docker compose -f compose.production.yaml up -d --wait
```

Проверить [https://forma.inflake.fun/api/health](https://forma.inflake.fun/api/health),
затем [https://forma.inflake.fun](https://forma.inflake.fun): интерфейс должен
запрашивать логин **forma**, пароль — `LCT_ACCESS_TOKEN`. Только проверка
`/api/health` общедоступна; материалы и настройки требуют входа.

Приложение представляет общее рабочее пространство с одним паролем. Все,
кому он выдан, имеют доступ к общим файлам и настройкам AI. Это не система
изолированных аккаунтов для посторонних клиентов.

Для автоматического обновления установить в серверном `.env`
`LCT_WATCHTOWER_ENABLED=true`, оставить `FORMA_TAG=main` и повторить `up -d`.
Это лишь метка: Watchtower должен уже работать, читать этот контейнер и иметь
учётные данные registry. Публикация `main` тогда может заменить приложение
во время задания; выпускать после завершения активной генерации.
По умолчанию обновление ручное, чтобы первый выпуск не зависел от неизвестных
настроек Watchtower. Сам Watchtower этим проектом не устанавливается.

## 5. Свой домен на новом сервере без Traefik

Для уже настроенного Inflake использовать предыдущий раздел. Для отдельного
Linux-сервера в репозитории есть Caddy: он получает и продлевает TLS-сертификат.
Понадобятся свой сервер, DNS A/AAAA и открытые 80/443; стоимость сервера,
домена и AI оплачивается отдельно. Один HTTPS-прокси должен владеть этими
портами — не запускать overlay поверх сервера с занятыми 80/443.

Скачать репозиторий, создать `.env`, заполнить `LCT_DOMAIN` своим доменом и
`LCT_ACCESS_TOKEN` своим паролем. В DNS направить домен на этот сервер.

На новом сервере из корня репозитория собрать приложение и запустить HTTPS:

```sh
docker compose -f compose.production.yaml -f deploy/compose.https.yaml up -d --build --wait
```

Образ собирается локально: registry и GitHub-секреты для этого пути не нужны.
Overlay создаёт собственную сеть `forma-public` и отключает Traefik/Watchtower.
После запуска открыть `https://` со своим доменом: сначала вход `forma`, затем
интерфейс. В случае ошибки сертификата проверить DNS, доступность 80/443 и
логи командой на этом сервере:

```sh
docker compose -f compose.production.yaml -f deploy/compose.https.yaml logs --tail=100 proxy
```

## 6. Обновление, резервная копия и откат

Перед обновлением дождаться окончания заданий и сделать защищённую резервную
копию тома `forma-data` средствами сервера. Он содержит исходники, результаты
и ключ провайдера: архив требует такого же ограничения доступа, как `.env`.
Для согласованной копии временно остановить приложение. Отдельно сохранить
`.env`, а при использовании Caddy — его том `caddy-data` с сертификатами.

На Inflake обновление — `pull` и `up -d --wait` из раздела 4. После изменений
конфигурации обновить также серверный `compose.production.yaml` и `.env`:
Watchtower меняет образ, но не переносит настройки из Git.

Для возврата на предыдущую версию на сервере установить в `.env`
`FORMA_TAG` равным полному SHA прежнего успешного выпуска из Actions,
`LCT_WATCHTOWER_ENABLED=false`, затем выполнить `pull` и `up -d --wait`.
Том данных сохраняется. Откат образа не отменяет изменения файлов данных;
при несовместимости нужна резервная копия. Не удалять прежние образы и
резервные копии до проверки новой версии.
